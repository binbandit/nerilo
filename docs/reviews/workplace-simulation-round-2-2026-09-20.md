## Additional defects found in round two

### SIM-06: Docker history export failed at the UI boundary

Opening Changes for the ancestry-only repair failed with a missing `/tmp/result.bundle` error. The bundle existed inside the helper, but Docker's archive copy did not expose its tmpfs mount.

The helper now transfers raw binary bytes. The regression uses real Docker, verifies the exact merge head and both parents, and rejects an unexpected head. The retained browser task was retried successfully and its repaired PR was merged.

### SIM-07: approvals triggered unnecessary repair work

Adopting PR #2 immediately started an agent turn containing both a superseded change request and the reviewer's later approval. The turn made no changes, consuming time and inference unnecessarily.

Formal approvals remain in history but cannot trigger repair. A later decision supersedes the same reviewer's older change request, including after a future push. Unresolved discussions and substantive new reviews remain actionable. Focused regressions and a live read of the real PR verified filtering. In the final live pass, Nerilo observed WastedHippie's approval on `3b39e0b` and stayed ready/reviewing with exactly the same three turn IDs. More than a minute of subsequent observation produced no queued work or unnecessary repair turn.

### SIM-08: a normal follow-up was rejected after Nerilo's own publication

Codex published the initial checklist as `46dd7803`. Claude then edited the retained task workspace successfully, but Autopilot refused publication because the workspace still began at `d45f8a5`. No teammate had changed that PR branch.

The fix proves that the previous captured result exactly matches the task-owned published tree before continuing the cumulative workspace. Competing remote heads and changed prior trees still fail safely. The retained Claude result was retried through Save in the Autopilot dialog, with no new agent turn: `2a61da5` published atop `46dd7803` on the same PR. The real Docker regression also covers committed follow-ups and preserving both histories.

### SIM-09: historical events claimed the wrong revisions

The old PR #4 review was made against `98c21a2`, but its timeline showed the later head first seen by Nerilo. A passing CI event showed the post-merge target base, implying that was the base it tested.

Reviews now retain their actual reviewed commit; CI retains its checked commit. Unknown historical bases are omitted. The head and base at observation time are separate, explicitly labeled context. Legacy records are corrected on normal reads and upgraded during normal observation without duplicating history. Focused history/store/summary/timeline tests pass. The rebuilt browser displayed Reviewed revision `98c21a22` for the original review and Checked revision `df3c4428` for CI, with the later base explicitly marked Base when observed.

### SIM-10: adopting an existing PR produced false publication events

After the no-op adoption turn, PR #2's timeline said Pull request opened and Published changes, despite no new PR or commit. Adoption now records continued or observed existing PR semantics. A no-op result does not emit a publication event. Conservative legacy handling suppresses a false row only when recorded evidence proves that the completed turn made no change to an already published head. The browser now shows Observed existing pull request #2 and retains the real `2499bac` publication, with the false `50434c4` publication removed.
