# UI review · September 12, 2026

Nerilo should stay compact without making people squint or explain familiar controls twice. This pass compared `docs/assets/nerilo.png` against populated tasks, settings, management screens, and secondary controls.

## Changes

- Shared dialogs now use consistent 20px gutters, 16px headings, smaller gaps, and one surface through the footer. The overlay uses neutral colors instead of a blue tint.
- Project setup no longer accumulates two layers of spacing above advanced fields. Home options use one selection indicator per row.
- Custom-model and schedule dialogs restore focus to their triggers. Scheduling starts focus in the date field.
- Settings use a consistent row rhythm. Theme previews match the actual chalk/cobalt and neutral dark palettes. Source editors use the defined monospace font token.
- On narrow screens, a section menu replaces the clipped Settings category strip. Every category remains reachable.
- Projects, Agents, and Library share denser management rows. Project names open their tasks; branch metadata is plain text rather than another badge. Mobile action menus stay aligned with their rows.
- Autopilot exposes its three outcomes directly with Astryx radio controls. Git errors keep their details and retry action together.
- Task file details use a quiet dividing rule rather than a separate card. Session information uses a consistent disclosure and offers a labeled, copyable session ID. Removed the fabricated `nerilo/<task-id>` branch text.
- Queued messages retain their label and position when expanded. Full ordinary messages wrap in place rather than repeating below a “Hide message” label. Autopilot instruction disclosures use the same chevron treatment.
- Activity/history timestamps are 11px, and review previews no longer reduce already-muted text opacity.
- The narrow task composer bounds long model labels so model, tools, and scheduling controls can share a row.
- In-app navigation updates React state directly as well as the URL. A reproduced mobile case previously changed the address while leaving the old page visible.
- Export and MCP wording refers to the selected/daemon machine rather than assuming a local Mac.
