# Code review and repairs: 19 September 2026

The serious problem was unreliable evidence of success. A task could appear finished while its container still owned the workspace. A provider could report failure while the runner reported success. Autopilot could publish after local verification failed. Those are correctness failures, not matters of taste.

The original test run had **178 passes and 4 failures**. The four failures were real Git workflow failures caused by comparing canonical paths with paths containing a symlinked ancestor. Type checking and formatting both passed, which did nothing to detect these defects.

All findings listed below were repaired. The review covered the daemon, persistence and lifecycle code, Git and PR workflows, credentials, container runners, sandbox controls, shared protocol, web proxy, client state, review UI, theme integration, and development scripts. Existing uncommitted work was preserved. No repository history was rewritten.

## Findings and repairs

P1 means the defect can produce an incorrect execution, publication, credential, or retained-work outcome. P2 means a reliability, validation, or usability defect that still deserves a fix.

| Priority | Location | What was wrong and what changed |
| --- | --- | --- |
| P1 | [Engine reconciliation](../apps/daemon/src/engine.ts) | A terminal event released the task before Docker confirmed container exit. A queued turn or Git operation could then access a workspace still in use. Terminal events now remain pending until the container stops. An actual Docker fixture emits a result and deliberately stays alive to verify the boundary. |
| P1 | [Pause handling](../apps/daemon/src/engine.ts) | Pausing immediately finalized a turn without consuming an already emitted result. Reconciliation now stops the container, confirms its state, and retains its result before completing the pause. The Docker regression also checks that queued follow-ups survive. |
| P1 | [Autopilot publication](../apps/daemon/src/autonomy.ts) | Publication checked the agent exit code but ignored failed project verification. A successful agent is not proof of working code. Publication now requires a finished turn and successful recorded verification when present. A regression asserts that failed verification causes no export, push, or merge. |
| P1 | [Managed checkout validation](../apps/daemon/src/git-workflows.ts) | Valid checkouts under symlinked ancestors, including macOS `/tmp`, were rejected. The comparison now canonicalizes the managed root consistently while retaining containment and own-repository checks. All four original Git workflow failures pass. |
| P1 | [Provider execution](../containers/agent.mjs) | Terminal Codex and Claude error events could be logged and then discarded in favor of a zero process exit code. Terminal semantic failure now makes the turn fail. Fake CLI processes reproduce both providers' failure shapes and successful session continuation. Early stdin closure is also handled without bypassing cleanup. |
| P1 | [Workspace capture](../containers/git.mjs), [verification](../containers/verify.mjs) | Independent diff implementations mishandled binary changes, unusual filenames, large output, and index state. Both execution paths now capture a consistent tree with a temporary index and temporary object store, emit binary-capable patches, parse NUL-separated statistics, check Git failures, and flag incomplete output. Real Git tests cover patch application, binary files, Unicode, tabs, newlines, trailing spaces, index preservation, invalid revisions, and truncation. Docker verification covers a read-only workspace. |
| P1 | [Output redaction](../containers/mcp.mjs), [metadata output](../containers/metadata.mjs) | Imported API keys were missing from the redaction list, and replacing secrets in serialized JSON could damage the JSON itself. One shared credential inventory now covers direct keys, imported keys, OAuth values, and MCP values. Metadata is redacted structurally before serialization. Tests include quoted secret values. |
| P1 | [Result emission](../containers/runner.mjs) | A redacted diff was still described as a complete, applicable patch. If redaction changes the patch, the result now marks it incomplete so existing export/application checks reject it. |
| P1 | [Private files](../apps/daemon/src/private-file.ts), [startup configuration](../apps/daemon/src/config.ts) | Token creation used a check-then-write race, accepted empty credentials, and followed symlinks. Initialization now atomically publishes one complete owner-only regular file, rejects invalid token contents and special files, and never opens a token symlink. Concurrent subprocess startup and symlink tests cover this behavior. Machine identity uses the same primitive. |
| P1 | [Host commands](../apps/daemon/src/config.ts), [container commands](../containers/process.mjs), [failed CI logs](../apps/daemon/src/pr-observer.ts) | Soft termination was treated as a deadline even when a child ignored it or descendants kept pipes open. A late zero exit could also be mistaken for success. Commands now force termination at the deadline, close readers, and report timeout status. Host output is bounded; CI logs retain a bounded tail. Streaming decoding preserves split UTF-8 characters. Process fixtures exercise these cases. |
| P2 | [Request reading](../packages/protocol/src/http.ts), [daemon API](../apps/daemon/src/api.ts), [web proxy](../apps/web/src/app/api/[...path]/route.ts), [Claude login](../apps/daemon/src/claude-login.ts) | Body limits were checked after allocating the body, and the proxy read bodies without an equivalent streaming limit. Shared reading now counts bytes as they arrive and cancels oversized bodies. The ordinary and skill-import limits remain distinct. Tests cover missing Content-Length, multibyte input, cancellation, and HTTP 413. |
| P2 | [API command identity](../apps/daemon/src/api.ts) | Creation and follow-up operations shared one global idempotency namespace. Reusing a key for another task could replay the wrong task's response. Keys now include the operation and task where relevant. API regressions exercise cross-task reuse and same-operation replay. |
| P2 | [Browser mutations](../apps/web/src/lib/api.ts) | Retrying after the server accepted a request but its response was lost generated a fresh key, permitting duplicate work. Uncertain submissions now retain their key for an identical retry in the current page session; successful responses release it so intentional later submissions remain possible. The regression simulates losing the first response after acceptance. |
| P2 | [Page refresh](../apps/web/src/app/page.tsx), [refresh coordination](../apps/web/src/lib/refresh.ts) | Polling, navigation, and event notifications could launch overlapping loads whose responses arrived out of order. Refreshes are now serialized and bursts request one trailing refresh. Navigation and component-lifecycle checks prevent stale task responses from being applied. Tests cover overlap and recovery after failure. |
| P2 | [Imported login validation](../apps/daemon/src/credentials.ts) | Any JSON object, including an array or an empty object, was accepted as a login. File existence was then treated as readiness. Imports now require a nonempty API key or access token; malformed retained authentication reports disconnected. Login and mode files are atomically replaced. Subprocess tests use disposable credentials and never import the user's real login. |
| P2 | [Autopilot scheduling](../apps/daemon/src/autonomy.ts) | Ordinary contention for a task lock counted as an Autopilot failure and could exhaust its retries. Locked tasks are now skipped until available. The regression holds the lock through three scheduler ticks and then confirms progress after release. |
| P2 | [Event stream](../apps/daemon/src/api.ts) | Already-aborted requests could leave streams and intervals alive. Slow readers could accumulate queued notifications. Streams now close immediately for an aborted request, remove abort listeners on cleanup, and respect backpressure. The proxy forwards the response body directly instead of maintaining another reader and cancellation layer. |
| P2 | [Project editing](../apps/daemon/src/api.ts) | Creation rejected duplicate project locations, but editing could create them. Both routes now use the same uniqueness check. The regression verifies rejection without changing the existing project. |
| P2 | [Task retry](../apps/daemon/src/api.ts) | The retry endpoint could requeue archived tasks even though other continuation paths required restoration. Retry now requires an unarchived task too. |
| P2 | [Git review UI](../apps/web/src/components/task-git-actions.tsx), [diff parsing](../apps/web/src/lib/diff-review.ts) | The compact patch view maintained another filename parser and counted lines by prefixes, excluding legitimate additions beginning with `++` and deletions beginning with `--`. It now shares the established Git path and hunk parser used by detailed review. |
| P2 | [API scheduling](../apps/daemon/src/api.ts), [daemon startup](../apps/daemon/src/index.ts) | Several fire-and-forget scheduler calls could reject without a handler. They now report failures consistently instead of producing unhandled rejections. Repeated API scheduling code is centralized. |
| P2 | [Test setup](../scripts/test-setup.ts), [test command](../package.json), fixture smoke scripts | Importing configuration during ordinary tests could initialize the real data directory. Git fixtures also inherited user signing and hook configuration. The standard suite and deterministic smoke scripts now use disposable data and isolated Git configuration. The explicitly live model smoke script keeps its separate semantics. |
| P2 | [Development launcher](../scripts/dev.ts), [web command](../package.json), [Next configuration](../apps/web/next.config.ts) | The web server's listening port was hardcoded while request validation used the configured port. The launcher and command now honor the same setting. An optional separate Next output directory permits isolated build and browser checks. |

## Simplifications

- The main runner and verification runner share one Git snapshot implementation and one bounded subprocess implementation. These are behavior-bearing boundaries with regression coverage, not cosmetic file splitting.
- Provider event interpretation is separate from container orchestration, so its success and failure behavior can be tested using real subprocesses without paid model calls.
- Machine identity and daemon token initialization share one private-file implementation. Credential replacement uses the same private-file module.
- The two patch views share filename and hunk parsing. Project creation and editing share uniqueness checks. The home composer computes its selected project once instead of repeating the lookup throughout its JSX.
- The web proxy no longer recreates a stream reader solely to forward the upstream stream.

Large orchestration files still exist. Splitting an API router into twenty files without changing ownership or invariants would not fix the failures above. The useful extractions here remove duplicated behavior or make a real boundary testable.

## Evidence boundaries

Live provider sign-in, paid model execution, GitHub publication, and GitHub merging were not exercised in this review. Provider output handling and publication decisions were tested with subprocess and service fixtures. Docker enforcement and Git operations used actual Docker and Git. No production database or real task was used for the fixtures.

To activate the container fixes in normal use, rebuild the agent environment with `bun run image:build`. Validation used a separate test image and temporary web/daemon ports; those fixture servers have been stopped.

The passing suite establishes the repaired behavior above. It is not a claim that every possible execution path or future provider behavior has been proven correct.
